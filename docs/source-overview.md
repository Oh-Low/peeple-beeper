# Source overview

What each source file under `firmware/`, `hal/`, `tools/`, and `emu/` does, ordered from the files that define the pager down to host tooling and tests. Matching headers were read with each file. `hal/hal.h` is the hardware contract the two hardware directories implement, not a script of its own. `emu/third_party/stb_truetype.h` is a vendored font rasterizer used by the bench.

Wire bytes and retry timing live in [radio-protocol.md](radio-protocol.md). Screens and the tick live in [firmware-app.md](firmware-app.md). How the layers sit together is [architecture.md](architecture.md).

## The pager

**`firmware/src/beeper.c`** is the one object that is a pager, and the function that runs it. It holds the device identity, the contact book, an in-progress pairing session, the message radio, the locate state, and the screen. Init zeroes that and does not touch saved memory. Each tick loads saved state once through the hardware layer, creates an 8-byte identity if one is missing, samples GPS, then either advances pairing or dispatches radio frames to the message session and to locate. A finished pair or a received page is handed to the screen. The tick then updates locate, the compass view, send status, and tracking prompts, skips the knob on a tick when a page arrived, draws the screen, and writes memory only when the saved image changed. Reset clears the device, marks memory as loaded, saves, and stops the vibrator.

**`firmware/src/screen.c`** is the screen state machine. It keeps the current screen, the highlighted row, the inbox, the outbox, and pointers into identity, contacts, pairing, the message radio, and locate. Home is a list — Inbox, Compose, Outbox, Peeple (locate someone or add a contact), Settings, and Beeple — drawn beside the chosen 64×64 mascot. Frames are drawn into a local 128×64 buffer, inverted when dark mode is on, and flushed only when the pixels changed. Encoder turns move the highlight or the text caret and wrap at the ends; press confirms; Back climbs. Several screens ignore turns. Sending picks a contact and either a preset or a typed body, then shows the name with SEARCHING, then success or a will-try-again failure. The outbox shows Retry, a time, or Fail, and pressing Fail sends again. A received page is stored first, then vibrates, beeps, and flashes New Beep with the sender, time, and text, unless a send is already on screen.

**`firmware/src/message.c`** is the message radio. One outbox slot holds the destination, the text, a random message id, and the sender's mascot index. A page and a locate may both be armed. The first frame of either waits for `beeper.c`, which sends a locate attempt or a locate reply ahead of a page on that tick. The contact's session key seals the message id, mascot, and text with a nonce and a MAC, and the frame starts with a hop limit of three. Up to nine transmissions reuse that message id with a fresh nonce: the first four are ten seconds apart, then the gap becomes a minute, and a busy locate pauses them. When those tries are exhausted, or a retry cannot be built, the send fails. An acknowledgement counts only while a send is in flight, only from that destination, only for a nonce this radio stored, and only with a matching MAC. A page from a known contact is opened with that contact's key, a valid mascot index is saved on the contact, and the page is shown once among the last 24 sender-and-message-id pairs. A page is acknowledged after the seal opens, including a repeat that is not shown again. A bad seal is dropped. Pages and acks for other nodes go to the relay. `beeper.c` is the one that reads the radio: it hands locate frames to locate, drops pairing frames, and on each tick sends a locate attempt or a locate reply ahead of a page.

**`firmware/src/pair.c`** runs a twenty-second pairing session. Start makes sure the local identity exists, turns the radio into a short-range whisper mode, and holds a hello: a fresh ephemeral, a nonce, the node id, the display name, and a mascot index. Frames weaker than −45 dBm are ignored. Every 400 ms the session sends that hello, then an acknowledgement once another node's hello is pending, then a closing leave once that acknowledgement matches. The ack and the leave both carry a confirmation hash of the two hellos, and each is accepted only from the pending node and only when addressed here. A matching leave is sent back, and the contact book stores the peer's id, name, mascot, pairing time, and a session key derived from both node ids and both ephemerals. A different id or ephemeral throws away the pending acknowledgement. Success leaves whisper mode and vibrates. Timeout, a full book, or a leave that arrives too early aborts.

## On the air

**`firmware/src/frames.c`** is the binary codec for every frame. Each one starts with a kind and version 1. Hello carries a node id, a 32-byte ephemeral, an 8-byte nonce, a length-prefixed name, and one mascot byte. Hello-ack answers a hello, and pair-leave ends a pairing; both carry a source id, a destination id, and a confirmation. A page carries destination and source ids, an 8-byte nonce, a hop limit, a length-prefixed body, and a MAC. A page acknowledgement and a location request use that header without the length and body. A location reply is a page whose body is eleven bytes. Encode returns the size, or zero on bad input. Decode copies fields only when the kind, version, and length all match. A separate call can rewrite the hop limit on a page, ack, location, or location request and leave the MAC alone.

**`firmware/src/crypto.c`** has one primitive, SHA-256. A 16-byte session key is the leading bytes of SHA-256 over the two 8-byte device ids and their 32-byte ephemerals, ordered so the bytewise-smaller id comes first. A pairing confirmation is the leading 16 bytes of SHA-256 over the two hello messages in that same order. Page plaintext is XORed with a repeating 32-byte SHA-256 of the session key and an 8-byte nonce. Integrity is an 8-byte tag, the leading bytes of SHA-256 over the key, the nonce, and the ciphertext. Opening checks that tag in constant time and decrypts only after it matches. An acknowledgement and a location request are authenticated the same way, over the key, the nonce, and the fixed bytes ACK or REQ.

**`firmware/src/relay.c`** is a store-and-forward cache of up to 24 records, keyed by message type, sender node id, and the frame's nonce. A new request or reply is remembered. A forward is armed only when the remaining hop count is greater than one, and a request is armed only when a reply from its destination with the same nonce is not already stored. The stored copy has its hop count reduced by one and waits a random 80 to 400 milliseconds, taken from the hardware clock and two random bytes. Hearing the same frame again only postpones a send that is still waiting. A reply cancels the pending request with the same nonce whose sender is the reply's destination. When the cache is full the oldest record is dropped. Each tick sends every frame whose delay has elapsed, once, and keeps the record so it is not armed again.

## Who the device is, and what it remembers

**`firmware/src/store.c`** packs the whole device into one little-endian blob. It starts with the magic bytes `PB01` and a version; writes emit version 9, and reads accept versions 1 through 9, defaulting any field an older version lacks. After that come the node id and display name, contacts, saved preset messages, inbox rows, outbox rows, the last GPS fix and its clock time, whether tracking is open, whether the clock and battery are shown, dark mode, the chosen mascot, and whether the backlight is on. Strings are a length byte plus characters. With no identity yet, the encoding is empty. Save still calls the hardware store with a zero-length buffer, which clears whatever was stored. If the image would exceed the storage budget, inbox rows are dropped first, then outbox rows, and RAM is shortened to match. A load is applied only when the blob parses exactly to its end. A hash of the image is kept, and a later sync writes only when that hash changed.

**`firmware/src/contacts.c`** is the in-memory address book, 256 rows. A contact is a node id, a display name, a session key, a pairing time in milliseconds, and a mascot index. Lookup is by node id. Upsert writes the id, key, and time, keeps a mascot only when the index is one this firmware knows, and trims the name; a blank name is `identity_blank_name`. An existing id is overwritten in place. A new contact is inserted at the front and older rows shift down; a full book rejects the insert. Changing a mascot updates only a row that is already there. Listing copies as many leading rows as the caller has room for and returns the true count. Delete closes the gap.

**`firmware/src/identity.c`** is a caller-owned record: eight id bytes, a flag that the id exists, and a display name capped at the length a page can carry for a sender. If the flag is already set, load-or-create does nothing; otherwise it fills the id from the hardware random source. Names keep printable ASCII, codes 32 through 126. Reading the name returns the stored string when it is non-empty, an empty string when there is no id, and otherwise the last four hex digits of the id.

## Finding another pager

**`firmware/src/locate.c`** asks a paired contact for a position, and answers when asked. A request goes out only while both locate and the message radio are idle, and only to a contact. It carries both node ids, a random nonce, a hop limit, and an authentication code, and it is resent every two seconds for at most four tries. A reply counts only while waiting, only if it is addressed here, from that contact, on a nonce this side sent, and unsealed with the session key. The result is denied, a latitude, longitude, and time, or no sky. An older stored fix stands in for no sky and for no reply. `locate_init` starts tracking open. The first tick closes it when saved storage is missing or empty, so a new device asks before it answers. Open tracking answers immediately and suppresses a repeat warning from the same contact for twelve seconds. When tracking is closed, a contact allowed in the last half hour is answered immediately; other asks wait, one on screen and eight queued, until Allow sends the fix or Deny sends a refusal. Frames that are neither to nor from this radio go to the relay cache. The GPS receiver is powered for up to a minute about every half hour. A reply reads it only if it is already on, and otherwise sends the saved fix or an empty body. One valid fix is kept for replies and for the distance shown in feet or miles.

**`firmware/src/gps.c`** converts between a local east/north foot grid and latitude/longitude stored as 0.0001 arcminutes, so one degree is 600000. The scale is the WGS84 equatorial degree: 110574.2725 meters of latitude and 111319.4908 of longitude, at 0.3048 meters per foot, rounded half away from zero. North feet become latitude and east feet become longitude. The difference of two fixes is a north/east offset in feet, and the distance is the integer hypotenuse. Eight compass headings are split at the tangent of 22.5 degrees, with the boundary counted as a diagonal; the origin has no heading. Latitude prints as degrees and four-decimal minutes with N or S; longitude uses three degree digits with E or W.

**`firmware/src/heading.c`** turns a compass sample plus a north/east offset in feet into the arrow the screen can draw. Tilt of 20 degrees or less is flat, and a still sample with the vibration motor off is quiet. Otherwise the arrow stays off and the screen is told to hold flat, hold still, or both. The first good sample starts a hold timer. For the first 400 ms the view says do not move; after that it is ready. A zero offset draws no arrow. Otherwise the bearing is `gps_octant`. The device's own facing is eight sectors from `(degrees + 22) / 45`, with 0 centered on north and then clockwise. The arrow is the clockwise gap from where the device is facing to where the target is, so 0 means the top of the screen.

**`firmware/src/nmea.c`** parses one NMEA 0183 RMC sentence into a fix, for a PA1616S receiver. It accepts `$GPRMC`, `$GNRMC`, or any two-character talker plus `RMC`. If a checksum is present it must match the XOR of the bytes between the dollar sign and the asterisk; a missing asterisk is allowed. A non-RMC line or a bad checksum leaves the output untouched. Status `A` is a valid fix; any other status, including `V`, zeroes it. Latitude and longitude come from the `ddmm.mmmm` and `dddmm.mmmm` fields with N/S and E/W, stored as signed arcminutes times 10000, south and west negative. Time, speed, course, date, magnetic variation, and the mode character are ignored. The board stub holds the partial line. `nmea_push_byte` ignores a carriage return, parses on newline, and drops a line that does not fit, through that newline. The RAM HAL stores a fix the caller already built.

## Pixels and text

**`firmware/src/display.c`** draws into a caller-owned 1024-byte framebuffer for a 128×64 panel. The buffer is eight pages of 128 columns: the byte at page times width plus x holds eight vertical pixels, bit 0 on top, and coordinates off the panel are ignored. Callers can set, clear, or read a pixel, clear the buffer, draw a horizontal line, XOR a rectangle, and stroke a Bresenham arrow. Two column-major fonts cover space through tilde. The main face is 5×7 and advances 6 pixels, with a heart, a gear, and a hollow box for an unknown character. The small face is 3×6 and advances 4. Text stops at the right edge. Helpers measure a string, clip it with a single trailing dot, wrap on spaces and newlines, paint a 9-pixel inverted header, and OR a page-packed sprite into the buffer.

**`firmware/src/textedit.c`** is a short text field driven by a rotary encoder. Start copies an optional string up to a chosen maximum, puts the caret at the end, and highlights E. Turns walk a wraparound set: OK, delete, save when that action is enabled, space, then letters in `ETAOINSHRDL` and `CUMWFGYPBVK` order, then digits, then punctuation. Press inserts the highlighted character at the caret while under the limit, and after a letter the highlight returns to E. Delete removes the character before the caret. Save and OK return those results and leave the draft as it is. A desktop Backspace or a single printable ASCII byte edits the draft directly. The value copied out has trailing whitespace stripped. Draw paints a slanted header, a clock when one is supplied, an inverted caret kept on screen, and an inverted cell for the selection.

**`firmware/src/canned.c`** holds preset message texts. Up to sixteen saved strings, each no longer than a page body, sit in front of six built-in phrases that never occupy those slots: "On my way", "Running late", "Yes", "No", "Where are you?", and "Call me". Listing shows saved texts first, newest at the front, then the six defaults, and always reports the combined count even when the caller's array fills up. Adding strips trailing whitespace, rejects a blank, and does not store a string that matches a built-in. A duplicate already saved is moved to the front. Anything else is inserted at the front, and a full book drops the oldest saved entry.

**`firmware/art/art.c`**, with `beeple.h`, is the picture store. Each sprite is a const byte array of 1-bit pixels in the same page layout the display blits: a set bit is ink, bit 0 is the top pixel of an eight-row page, and the byte index is page times width plus column. The header publishes a width, height, and length for each picture. The source holds the bytes: side decorations, four arrows, and larger figures, twelve of which are 64×64 mascots. The mascot index itself is a separate one-byte value, with 12 known pictures and 255 meaning the other device has not said which one it uses. A contact and a sealed page store that byte, not the bitmap. `firmware/art/beeple.c` is the menu catalog: each index has a name and a pointer at those pixels. The screen asks `beeple_at`.

## What stands in for hardware

**`hal/emu/emu_hal.c`** is the in-memory hardware layer that tests and the desktop bench use. Init zeroes the state and fills the HAL function table the firmware calls. The display is a 128×64 page-packed buffer, and flush does nothing. Encoder events sit in a 32-slot ring that drops pushes when full. Back presses are a counter capped at eight. Transmit does not queue: a non-empty frame is truncated to 128 bytes and, if a hook is installed, handed to that hook. Receive is a 16-slot ring that stores the bytes, the RSSI, and the current millisecond time. Time, clock hour and minute, and a 100 KB nonvolatile array are plain fields the caller writes. GPS power starts on, and a fix is returned only when power is on and a valid sample has been installed. The setter clamps tilt to 0–90. The sample the firmware reads copies tilt through, wraps degrees into 0–359, copies the still flag, and reports the motor as on while a vibration interval is still ahead of the clock.

**`firmware/host/mesh.c`** is the desktop radio medium, up to sixteen nodes. Each node is a RAM radio plus pointers to its east and north position in feet; a null pointer reads as zero. Distance between two nodes is the hypotenuse of those deltas. RSSI exists only under 100 feet: −30 dBm at the transmitter, falling linearly by 60 dB across that span, rounded half away from zero. Linking installs a transmit hook on every radio. A send is handed on as the same bytes, tagged with the RSSI for that distance, into every other node still inside that span. The receive ring drops the frame when it is full and truncates past 128 bytes. The sender is skipped, and farther nodes receive nothing. There is no collision model. Clearing detaches the hooks and zeroes the mesh.

**`hal/beeper/beeper_hal.c`** is the Feather `hal_t` table. Host builds link it alone, and the weak `board_*` hooks keep the old stub behavior: no pins, empty radio, empty store, `now_ms` of 0. **`hal/beeper/board.c`** is linked only into `make beeper` and replaces those hooks. **`hal/beeper/sx1262_setup.c`** is the SX1262 command list, linked into the pager and the wire test. `board.c` drives the glass, knob, Back, RTC, RNG, GPS UART, compass, and the radio. Send transmits the frame it is given. Beep drives no pin. Vibe only records a deadline. The UART byte sink skips carriage returns, and a newline stores a fix only when the RMC parser accepts the line. With GPS power on, a later read copies that fix and returns its valid bit. Power starts on in the table; the Feather pin follows `gps_power`.

## The desktop bench

**`emu/main.c`** is one resizable high-DPI SDL2 window showing up to sixteen pagers. A, B, and C start 75 feet apart on an east-west line. Each 128×64 framebuffer is scaled 3×, with a gold border on the focused unit. Each column is a RAM hardware layer plus one pager, ticked every 16 ms from SDL's clock, with the local wall clock copied in and nonvolatile memory saved to a file. Clicking an LCD focuses it; a click with no drag is a shaft press; a vertical drag steps the encoder every eight pixels; the wheel turns the knob. Escape is Back. Arrow keys and j/k turn the knob; Enter and Space press it. Typing and Backspace go to the on-screen editor. The top bar adds a radio or removes the last one. N, E, S, and W move the focused radio 5 feet, or 25 with Shift, and the wheel under an LCD moves it north or south. Each radio lists the names of the others it can hear. Buttons set tipped or flat, still or moving, sky or no sky, force a GPS sample, and turn heading by 15 degrees, or 45 with Shift.

**`emu/seed.c`** provisions the simulated units so they can message each other without walking through pairing. Each unit has a pager, a short name, and a hardware handle. Seeding loads or creates each identity, fills a blank display name from the unit name, and looks at every pair. Contacts that already exist on both sides are left alone. A contact that exists on only one side is copied onto the other, keeping the existing session key. If neither side has the other, one side draws a session key and both books store the peer. Adding a unit sets its display name and installs a fresh shared key with every unit already present. Removing a unit deletes that node id from every remaining book.

**`emu/font.c`** turns one TrueType file into an SDL texture atlas for the bench chrome, using stb_truetype. The atlas is 1024×1024, rasterized at 15 points times the window DPI, covering ASCII 32–126 plus the degree sign and the minus sign. Coverage is stored as alpha on white. Drawing and measuring decode UTF-8 of up to three bytes; anything else becomes a question mark. Draw treats the y coordinate as the top of the line, places the baseline at that top plus the ascent, and copies each glyph quad. Width is the advance divided by DPI. Passing a null path rebuilds the atlas from bytes already read.

## Art pipeline

**`tools/beeple_to_art.py`** packs the mascot PNGs into 64×64 firmware bitmaps. It takes explicit paths, or every PNG in the Beeple art folder, and uses the PNG converter to pack pixels. Twelve known filenames must be present and keep fixed C symbol names and labels of at most ten characters. Any other PNG is appended in filename order. Each image is copied into a 64×64 window from the top-left, except one picture that starts three rows down; cells past the source take the source's top-left pixel. If the mean color of the original border is dark, the bitmap is inverted so a black surround becomes paper. With `--write` it updates the art header and source, rewrites the mascot table in `firmware/art/beeple.c`, and sets the mascot count.

**`tools/png_to_art.py`** turns one or more PNGs into a 1-bit C array in the display's page layout. It checks the PNG signature, reads the header, palette, and transparency chunk, concatenates the image data, rejects interlacing and bit depths other than 1, 2, 4, or 8, inflates, and undoes the standard row filters. Alpha under 128 is paper. Ink is an RGB average under 128, or the opposite with `--invert`. Rows pack into pages of eight with bit 0 on top. The filename, or a single `--name`, becomes an `art_` symbol. Without `--write` it prints the macros and the hex array. With `--write` it adds or replaces that symbol in the art header and source.

## Shared helpers and tests

**`firmware/src/util.c`** is a few shared helpers. Two buffers compare equal by length and bytes, or over a fixed count. An ordering compare puts the shorter buffer first after a shared prefix. Elapsed time is an unsigned subtraction, and a deadline counts as reached when the unsigned gap from the deadline to now is under half the 32-bit range, so a wrapped millisecond clock still works. String helpers count bytes up to a NUL, copy with a cap and a trailing NUL, and clip a long string by keeping one fewer character and adding a period.

**`firmware/tests/page_test.c`** checks a page between paired in-memory radios. A destination decrypts, shows the contact name, body, and mascot, stores the mascot on the contact, and acknowledges once; the sender becomes delivered. A repeat is acknowledged and not shown again. Nine unanswered sends use fresh nonces on a ten-second then sixty-second schedule, stay in sending after the ninth transmit, and fail after one more wait, with no tenth transmit. A user retry uses a new message id and is shown once; an acknowledgement of the first id still delivers.

**`firmware/tests/relay_test.c`** checks the forward cache. A third node relays a page or an ack once after a jitter delay, with the hop count reduced and the nonce kept, stays silent before that delay, skips a copy it already sent, and drops a hop count of one. Hearing the frame again before the send restarts the delay. An ack heard first, or during the wait, blocks the page; a different nonce is still relayed. A full cache drops the oldest nonce. An oversized frame is remembered, clamped, and not transmitted.

**`firmware/tests/gps_test.c`** checks the foot grid and RMC. Foot offsets quantize to arcminutes. An RMC sentence, including one fed as UART bytes through the board stub, posts the same numbers.

**`firmware/tests/heading_test.c`** checks the arrow. It stays hidden while the unit is tipped, moving, or vibrating, then settles. Facing east, a target ahead is the matching octant.

**`firmware/tests/receiver_test.c`** checks receiver sleep. A sampled fix survives the receiver sleeping and a later no-sky listen. After the unit moves, the next listen stores the new fix and powers the receiver off.

**`firmware/tests/locate_test.c`** checks the position exchange and tracking consent. A reply at 75 feet due east and one at a 212-foot northwest corner both produce a distance and an arrow; with no fix of our own the arrow stays hidden, and a reply with no fix reads as no sky. A bad MAC or an unknown contact is ignored. Four unanswered tries become no reply. An unpaired middle node relays a request 150 feet east. Locate and paging never transmit in the same window. A refresh keeps the previous fix and time when the new reply times out or reports no sky, and our own move updates the distance. With tracking closed, asks queue until Allow or Deny, and keys that arrived before the prompt are ignored; Back denies. An allow stays quiet for the rest of its window. Open tracking warns once per warning interval.

**`firmware/tests/mesh_test.c`** checks RSSI and who hears whom on the fake air, which goes silent at 100 feet. RSSI is −30 at the origin, a link exists at 75 feet, and 100 and 150 feet are silent. On a line at 0, 75, and 150 feet, a send from either end is heard only by the middle.

**`firmware/tests/seed_test.c`** checks contact seeding. Seeding three named units gives each two contacts, and the shared names and 16-byte session key match. Adding a fourth radio keeps the existing key, gives the newcomer three contacts, and removing it drops it from the others.

**`firmware/tests/pair_test.c`** checks restarting a pair. Re-running add for two pagers that are already paired and sitting together returns both to the menu on one key. Aborting one side after both hold hello acknowledgements, then minting a new ephemeral under the same node id, makes the peer drop the old acknowledgement and finish pairing on matching keys.

**`firmware/tests/store_test.c`** has two checks on the RAM hardware layer. A save must reject one byte over the storage budget, accept a zero-length write, and accept a write of exactly that budget. A populated pager is then saved and loaded into a fresh one. The load restores the same node id and the name Ada, one contact Bob with the same session key and mascot 2, the preset text "See you", and an inbox body "hi" at 14:32. A sent outbox row stays sent with its sent and ack clocks. A row saved while still sending reloads as failed, with no ack clock. The locate fix, a closed tracking setting, a hidden clock-and-battery row, dark mode, a backlight that is off, and mascot 3 all come back, and the menu art is 64 pixels wide.
